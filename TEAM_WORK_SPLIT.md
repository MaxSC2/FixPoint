# FixPoint — распределение ответственности

## Роли

### ChatGPT — архитектор, frontend/UI и независимый QA

Владеет:
- `app/Views/**`
- `public/assets/**`
- `prototype/**`
- `docs/**` (UX, интеграционные договорённости, roadmap и QA; требования изменяются только согласованно).

Результаты: дизайн-система, страницы и состояния интерфейса, адаптивность, клиентские сценарии, визуальные проверки, интеграционная проверка и ревью PR агента.

### Coding agent — backend, БД и DevOps

Владеет:
- `app/Controllers/**`
- `app/Services/**`
- `app/Repositories/**`
- `app/Middleware/**` и `app/Security/**`
- `database/**`
- `tests/Backend/**` и `tests/Integration/**`
- `Dockerfile`, `docker-compose.yml`, `.github/workflows/**`
- bootstrap/router/config в соответствии с контрактом.

Результаты: PHP 8.3+, MySQL 8, PDO, миграции, seed, серверная авторизация и роли, бизнес-логика, безопасность, Docker, CI и тесты.

## Совместные границы

- Контракт `docs/10-INTEGRATION-CONTRACT.md` обязателен для обеих сторон.
- Новый маршрут/поле со стороны интерфейса сначала фиксируется в контракте и согласуется с агентом.
- Новое состояние/ошибка со стороны backend сначала предлагается к внесению в контракт.
- Общие файлы `public/index.php`, `bootstrap.php`, `routes.php`, `composer.json` меняет агент; ChatGPT отправляет предложения отдельным списком.
- Не редактировать чужие зоны без согласования.

## Git-процесс

- `main` — стабильная ветка; `develop` — интеграционная.
- Задачи — `feature/<номер>-<slug>`, PR — в `develop`; релизный PR — `develop -> main`.
- Один PR — одна задача. Запрещены force push в общие ветки и прямые коммиты в `main`/ `develop`.
- До merge обязательны проверки, описание файлов, команды тестирования и фактические результаты.
- Не коммитить `.env`, токены, реальные персональные данные и пароли.

## Условия приёмки

Задача не считается готовой по одному сообщению агента. Нужны проверяемый commit/PR, фактические тесты, соответствие контракту и отсутствие изменений в чужой зоне.
