# FixPoint — права на публикацию транскриптов YouTube

**Дата:** 18.11.2026  
**Статус:** вопрос зафиксирован, решение принимает владелец проекта. В этом проходе файлы не удалялись, не переписывались и не вычищались из истории.

> Это не юридическая консультация. Ниже — инженерная оценка риска и рекомендуемый безопасный вариант публичного пакета.

Дополнительно подробные пересказы уроков содержит `docs/32-ASSIGNMENT-VIDEOS-TRANSCRIPTS-2026-11-17.md`; темы и ответы по видео — `docs/27-MODULE-4-DEFENCE-NOTES.md`. Пересказ своими словами имеет меньший риск, чем дословный текст, но всё равно производен от чужого материала.

## 2. Почему это потенциальный риск

Условия использования YouTube ограничивают скачивание и распространение Контента, кроме случаев, разрешённых правообладателем, законом или самими условиями: <https://www.youtube.com/t/terms>.

Практические факторы:

- видео принадлежат третьему лицу (автору курса), а не владельцу FixPoint;
- явная лицензия на перераспространение в документах курса не подтверждена;
- публичный GitHub-репозиторий — это распространение, а не личное хранение;
- даже удаление файлов из текущего HEAD не стирает их из истории Git и форков; для полного удаления потребовалась бы отдельная процедура, которую нельзя выполнять без решения владельца.

Это риск прав/ToS, а не установленное нарушение. Оценку должен дать владелец с учётом правил сдачи и требований преподавателя.

## 3. Рекомендация

**Публично безопасный пакет:**

- ссылки на видео и их ID;
- названия, длительности, номера заданий;
- собственные краткие конспекты и выводы «что это значит для FixPoint»;
- таблица сопоставления требований и реализации;
- код валидатора и инструкция по воспроизведению проверки;
- результаты валидатора без полного текста (счётчики, хэши, ID).

**Приватно / локально:**

- `*.ru.vtt`, `*.en.vtt`;
- `*.ru.txt`;
- `full-transcript.md`;
- `*.info.json`;
- при желании — расширенные дословные выдержки.

Полный текст нужен для проверки и подготовки к защите, но не обязан находиться в публичном репозитории.

## 4. Варианты решения владельца

| Вариант | Плюсы | Минусы / риски |
|---|---|---|
| **A. Оставить как есть** | Ничего не меняется перед дедлайном; пакет доступен проверяющему | Публичное распространение полного текста; риск претензии/ToS |
| **B. Оставить публично только метаданные и конспекты, полный текст — в приватном хранилище** (рекомендуется) | Снижает риск; сохраняет проверяемость выводов | Нужно перенести 66 файлов; удаление из HEAD не очищает историю |
| **C. Удалить полный текст из HEAD и подготовить отдельную процедуру очистки истории** | Максимально снижает дальнейшее распространение | Переписывание истории запрещено в текущем проходе; требует отдельного согласования и координации с GitHub |
| **D. Запросить разрешение у автора курса** | Устраняет неопределённость | Требует времени; ответ может быть отрицательным |

**Рекомендация:** вариант **B** после сдачи или по решению владельца; до решения не удалять и не переписывать файлы, чтобы не сломать воспроизводимость проверки и не создать незапланированную историю.

## 6. Если владелец выберет вариант B

Безопасная последовательность (после подтверждения):

1. Создать приватное хранилище (приватный репозиторий, защищённый артефакт или локальный архив).
2. Перенести туда `assignment/subtitles/*.vtt`, `*.txt`, `full-transcript.md`, `*.info.json`.
3. В публичном репозитории оставить `README.md` с ссылками/названиями/длительностями, `_index.json` без текста и краткие конспекты.
4. Обновить docs/32: убрать дословные фрагменты, оставить выводы и ссылки на приватный пакет.
5. Отдельно решить, нужна ли очистка истории; без решения владельца её не выполнять.
