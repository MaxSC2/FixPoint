### 1.1. Метод получения

YouTube отдаёт автосубтитры «бегущей строкой»: каждая фраза приходит дважды — как текущая строка и как предыдущая в следующем кадре. Наивное склеивание давало текст с двойным повтором каждой фразы. Транскрипты собраны по последней строке каждого кадра с дедупликацией. Прежняя проверка «финальная реплика TXT = финальная реплика VTT» доказывала только отсутствие очевидного обрезания в конце; теперь её заменяет воспроизводимый валидатор (раздел 5).

## 2. Задание 9 — требование DOCX и темы видео

**Требование DOCX по заданию 9:** «Прослушать три видео без названий». Это отдельный пункт учебного плана, а не три функциональных критерия продукта.

Темы, показанные внутри этих видео, полезны для сопоставления с FixPoint, но **не являются отдельными обязательными функциями**, пока DOCX не требует их где-то ещё. В частности, редактор четырёх страниц с мета-тегами и Basic Auth — содержание уроков, а не автоматически «недостающие функции» FixPoint.

### Видео 1 — редактирование текстов страниц

Задача урока: дать администратору менять `title`, `meta description`, `meta keywords` и полный HTML-текст каждой из четырёх страниц (`index`, `articles`, `lessons`, `contacts`), которые хранятся в таблице `settings`.

Реализация в уроке:

- `edit_text.php` — копия `edit_lesson.php`: `SELECT title, id FROM settings` + цикл `do…while` со ссылками `edit_text.php?id=…`; при наличии `id` — `SELECT * FROM settings WHERE id=…` и форма с полями title / meta_d / meta_key / text + скрытое поле `id`.
- `update_text.php` — копия `update_lesson.php`: проверки `isset()` для title, meta_d, meta_key, text; `UPDATE settings SET title=…, meta_d=…, meta_key=…, text=… WHERE id=…`; сообщения «страница обновлена / не обновлена / введена не вся информация».
- Ссылка «Редактировать тексты» в левом блоке админки ведёт на `edit_text.php`.
- Автор по ходу ловит свою ошибку: лишняя запятая в `UPDATE` → «страница не обновлена». Методический акцент: проверять результат после каждого шага.

### Видео 2 — защита админки

Задача урока: закрыть админку паролем, чтобы посторонний не мог набрать `/admin` и менять сайт.

Реализация в уроке:

- Готовый файл `login.php` из архива дополнений копируется в папку `admin`.
- В **начало каждого** PHP-файла админки добавляется `include "login.php";` — до любых других инструкций.
- В БД создаётся таблица `users` из трёх полей: `id` (INT, AI, PK), `user` VARCHAR(50), `pass` VARCHAR(50); вручную добавляется администратор.
- Скрипт использует HTTP Basic Auth: браузер показывает системное окно «имя пользователя / пароль», скрипт сверяет пару с таблицей и либо отдаёт страницу, либо снова показывает окно.
- Проверка: прямой заход на `edit_lesson.php` без авторизации → запрос пароля; после ввода → доступ; после перезапуска браузера → снова запрос.

### Видео 3 — финал курса

- Итоговая схема: две части сайта — публичная (только читает БД) и административная (читает и пишет), плюс БД из четырёх таблиц (`settings`, `lessons`, `articles`, `users`).
- Перенос на хостинг: экспорт четырёх таблиц из локального phpMyAdmin (файл или SQL-дамп) → создание БД и пользователя на хостинге → импорт → правка реквизитов подключения в `bd.php` в корне и в `admin/blocks/bd.php`.
- Дополнительно: место под Google AdSense, замена идентификаторов формы подписки SmartResponder, анонс следующего курса.

### Как это соотносится с FixPoint

- Защита админки в FixPoint реализована **сильнее**, чем в уроке: сессии + `password_hash` + CSRF + RBAC (в уроке — Basic Auth с паролем в открытом виде в БД). Это сопоставление, а не отдельный балл за задание 9.
- Редактирование контента реализовано **частично**: `AdminContentController` умеет править блок «О нас» (`site_content_blocks`), но не четыре страницы с мета-тегами. Это разрыв с материалом курса, а не автоматически проваленный критерий DOCX.
- Перенос на хостинг к FixPoint неприменим: проект запускается через Docker Compose, публичный deployment не заявляется.

### 3.3. Заголовки и мета-теги: что статично, что из БД

| Элемент | Источник в коде | Статус |
|---|---|---|
| Общий `<title>` публичных страниц | `$pageTitle` задаётся в контроллерах/шаблонах (`HomeController`, `PageController`, `home.php`, `about.php`, `contacts.php`) | **Статический текст в коде**, не из БД |
| `<title>` страницы услуги | `$service['name'] . ' - ' . app.name` в `ServicesController` | **Из БД** — единственное исключение |
| `<title>` кабинетов и админки | Строки в контроллерах + `app.name` | **Статический текст в коде** |
| `<meta name="description">` | Одна статическая строка в `app/Views/layouts/header.php` | **Статический текст**, одинаковый для всех страниц |
| `<meta name="keywords">` | Отсутствует | **Нет** |
| Мета-поля урока (таблица `settings`) | В FixPoint нет таблицы страниц с `title/meta_d/meta_key` | **Нет** |

Поэтому строку «`title` из БД ✅» использовать нельзя. Корректная формулировка: «общий `title` — статический; `title` карточки услуги — из БД; `meta description` — статический; `keywords` — отсутствуют».

## 4. Разрывы с материалом курса, которые можно закрыть без риска

Это не P0 и не обязательные пункты DOCX. Перечислено, чтобы не выдавать темы уроков за выполненные требования.

1. **`meta description` из БД** — добавить колонку в `site_content_blocks` и выводить в лейауте; 1 миграция + 1 шаблон + 2 теста.
2. **Редактирование текста контактов** — расширить `AdminContentController` вторым блоком по образцу «О нас».
3. **Редактирование всех четырёх страниц** — самый близкий к уроку вариант, но требует отдельной таблицы страниц и решения, какие тексты действительно живут в БД, а какие остаются в шаблонах.

Ни один из пунктов не входит в обязательный минимум P0 и не должен ломать текущий HEAD перед защитой.

```powershell
# unit-тесты валидатора
```

Валидатор проверяет: наличие и непустоту 31 VTT + 31 TXT; разбор VTT и порядок таймкодов; соответствие ID индексу и DOCX; объём TXT против индекса (ratio 0.8–1.35 и абсолютный допуск); короткие и дублирующиеся тексты; трассируемость TXT→VTT (покрытие не ниже 95 %); расхождение длительности как warning; долю пустых cue как warning.

## 6. Source Audit: два независимых факта

`Module 4 source audit` намеренно разделяет два статуса, которые нельзя смешивать:

1. **Live-эндпоинт YouTube.** `yt-dlp` обращается к YouTube за списком дорожек. Статус зависит от времени, IP и антибот-политики: в одном прогоне он может быть `available`, в другом — `blocked_by_youtube`. `blocked` означает **unverified**, а не «субтитров нет». Наличие локального файла не делает live-проверку «verified». В локальном прогоне 18.11.2026 получено `available=31`; в предыдущем CI-прогоне было `blocked_by_youtube`. Актуальный статус CI фиксируется в артефакте и в `docs/37`.
2. **Локальный пакет.** Валидатор проверяет закоммиченные `ru.vtt`/`ru.txt`: наличие, разбор, порядок таймкодов, ID, объём, трассируемость. Успех этой проверки означает «локальный пакет найден и структурно валиден», но не «человек посмотрел видео».

Отчёт workflow `artifacts/module4/module4-video-study.md` содержит обе секции; `transcript-validation.md` — детальный отчёт по файлам.

## 7. Права на публикацию транскриптов

Репозиторий публичный. Полные субтитры и объединённый транскрипт — производные от сторонних видео YouTube; это потенциальный вопрос прав и условий использования, а не юридическое заключение. Решение принимает владелец проекта. Подробности и рекомендуемый безопасный публичный пакет — `docs/35-TRANSCRIPT-RIGHTS-2026-11-18.md`.

До решения владельца существующие файлы не удаляются, не переписываются и не вычищаются из истории.
