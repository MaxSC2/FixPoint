# TASK-001 — Backend foundation для FixPoint

**Исполнитель:** coding agent  
**Приоритет:** P0  
**Тип:** backend / infrastructure  
**Зависимость:** database design и integration contract.

## Цель

Создать чистый, запускаемый PHP + MySQL каркас FixPoint, на который можно подключать интерфейсные шаблоны. Не реализовывать все бизнес-модули сразу и не копировать чужой код из SkinTrade.

## Обязательный результат

1. Минимальная структура приложения согласно архитектуре проекта.
2. PHP 8.3+, MySQL 8, PDO, `utf8mb4`, InnoDB.
3. Конфигурация через `.env`; в репозитории остаётся только `.env.example`.
4. Единый bootstrap/front controller и корректная обработка ошибок.
5. Простой router с параметрами маршрута и HTTP-методами.
6. Общие helpers: escaping, redirect, CSRF, flash messaging (имена задокументировать).
7. Единый renderer PHP views, совместимый с integration contract.
8. Миграции для `users`, `service_categories`, `services`, `repair_requests`, `request_status_history`, `request_comments`.
9. Seed: категории, 8–12 услуг, тестовые роли и несколько заявок. Пароли тестовых аккаунтов документировать только для локальной среды.
10. Docker Compose для PHP и MySQL, healthcheck БД, volume для данных и понятная команда запуска.
11. Smoke tests: приложение поднимается, PDO соединяется, главная отвечает HTTP 200, неизвестный URL даёт 404.
12. README с запуском на чистой машине.

## Ограничения

- Не создавать шаблоны в `app/Views/**` и не менять `public/assets/**`: это frontend-зона.
- Не менять документы требований без согласования.
- Не внедрять Laravel/Symfony/React/Vue без обоснования.
- Не хранить секреты, реальные персональные данные и пароли в git.
- Не оставлять фиктивные успешные обработчики форм.
- Не писать SQL непосредственно в контроллерах.
- Статусы заявок в последующих задачах должны меняться через единый `RequestStatusService`.

## Не входит в TASK-001

Полноценная регистрация/авторизация, бизнес-обработка заявок, CRUD админки и финальный дизайн страниц. Эти задачи начнутся после ревью основы.

## Критерии приёмки

- [ ] Новый разработчик запускает систему по README с чистого клона.
- [ ] `.env` не отслеживается git, `.env.example` содержит безопасные placeholders.
- [ ] PDO использует исключения и корректную кодировку.
- [ ] Миграции выполняются предсказуемо.
- [ ] Seed безопасен при повторном запуске.
- [ ] Есть 404/500 без утечки внутренних деталей.
- [ ] Smoke tests проходят.
- [ ] PR содержит список файлов, команды запуска/тестирования и реальный вывод проверок.
- [ ] Frontend-owned paths не изменялись.

## Формат отчёта

Commit SHA и ветка; изменённые файлы; команды запуска и тестов; фактический результат; намеренно не реализованные пункты; открытые вопросы.
