# Правила разработки

## Git
- main — стабильная ветка.
- develop — интеграционная ветка.
- feature/<issue>-<slug> — рабочие ветки.
- PR направлять в develop; release PR — develop → main.
- Не пушить напрямую в main/develop, не делать force push общих веток.
- Перед изменениями проверить актуальный HEAD и dirty tree.

## Ownership
Владение путями закреплено в TEAM_WORK_SPLIT.md. Не редактировать чужие области без согласования. Общие bootstrap/router/contracts обсуждать заранее.

## Код
- PHP 8.3+, строгая типизация где уместно.
- PDO prepared statements.
- Controllers тонкие; SQL в Repository, правила в Service.
- Валидация серверная.
- Секреты и реальные персональные данные не коммитить.
- Комментарии объясняют причину, не пересказывают строку.
- Не добавлять зависимости без обоснования.

## UI
- Семантический HTML, адаптивность, keyboard focus.
- No fake success; ошибки сервера должны быть видимыми.
- Не выдавать mock data за реальные данные.
- Не показывать клиенту внутренние заметки.

## Тесты и отчёты
- До PR запускать релевантные tests/lint/smoke.
- Отчёт содержит точные команды и фактические результаты.
- Не заявлять прохождение теста, если он не запускался.
- TASK-002 не начинать до приёмки TASK-001.
