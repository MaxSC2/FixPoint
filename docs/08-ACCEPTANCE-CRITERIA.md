# Критерии приёмки FixPoint

## Запуск
- Чистый clone запускается по README.
- Docker Compose поднимает PHP и MySQL; БД healthcheck проходит.
- Миграции и seed выполняются повторяемо.
- `.env` не попадает в git.

## Пользовательские сценарии
- Гость просматривает услуги.
- Клиент регистрируется/входит и создаёт заявку.
- Клиент видит только собственные заявки.
- Администратор назначает мастера.
- Мастер фиксирует диагностику/смету.
- Клиент согласует или отклоняет смету.
- Мастер переводит заявку по разрешённой матрице статусов.
- История изменений отражает каждое изменение.
- Заявка завершается и не теряет историю.

## Безопасность
- Нельзя получить чужую заявку подбором ID.
- Роль проверяется на каждом серверном endpoint.
- CSRF invalid отклоняется.
- Пароли хешируются.
- В SQL используются prepared statements.
- HTML-вывод экранируется.
- Ошибки не раскрывают SQL/stack trace.
- Внутренние комментарии не видны клиенту.

## Интерфейс
- Нет горизонтального переполнения от 360 px.
- Клавиатурный focus видим.
- У форм есть label, validation feedback и error state.
- Списки имеют loading/empty/error/normal states.
- KPI и цены поступают из БД, demo данные маркированы.
- Нельзя показывать ложный успех при ошибке backend.

## Доказательства
Каждый PR прикладывает изменённые пути, команды, результаты тестов и шаги ручной проверки. Выполнение задачи без проверяемого commit/PR не принимается.
